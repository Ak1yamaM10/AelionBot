# AelionBot v0.42.2

这一版让无人值守的命令行运行更可靠，同时修了终端、补丁和批量读取里几处会让模型白白失败的地方。

## 简体中文

### 无人值守运行

- 用 `purpose=service` 启动、不带 tty 的命令，在命令行运行结束后继续存在：它在后台独立运行，输出写入日志文件。带 tty 的终端仍会在运行结束时关闭，需要长期运行的进程请不要带 tty。
- `exec_command` 在命令退出时立即返回，不再等到第一段输出。对已经退出的终端调用 `write_stdin`，会返回剩下的输出，而不是报错。
- 新增 `--web-search` 启用托管搜索，`--disable-tools` 隐藏指定工具。网页工具被关闭时，系统提示不再提到它们。
- 没有 Electron 时，`view_image` 也能工作，图片尺寸从文件头读取。
- 命令默认带 `DEBIAN_FRONTEND=noninteractive`，没人回答时区之类的安装提问，`apt` 不会一直卡住直到超时。调用方自己设置了这个变量时以它为准。

### 工具

- `tools_batch` 的步骤只能使用本次任务能直接调用的工具。被禁用或被隐藏的工具不能再借批量步骤运行，规划模式下的限制同样适用。
- 终端等待时间超过 30 秒时会缩短到 30 秒，不再直接拒绝。运行中的命令会返回已用时间，并说明暂时没有输出不代表卡住；`exec_stop` 会提醒不要中断安装和构建。
- `file_patch`：同一批补丁里，后一个补丁用的哈希可能落后于 Bot 自己刚写入的版本。只要文件内容仍然正好是 Bot 写的，补丁就会被接受，不再报 `FILE_CHANGED`。文件被外部修改过时仍会拒绝。

## English

### Unattended runs

- A command started with `purpose=service` and without a tty keeps running after the command-line run ends: it runs detached and writes its output to a log file. Terminals with a tty are still closed when the run ends, so start anything that must outlive the run without a tty.
- `exec_command` returns as soon as the command exits instead of waiting for its first output. `write_stdin` on a terminal that has already exited returns its remaining output instead of failing.
- New `--web-search` turns on hosted search and `--disable-tools` hides the tools you name. When the web tools are off, the system prompt stops mentioning them.
- `view_image` works without Electron; the picture size is read from the file header.
- Commands get `DEBIAN_FRONTEND=noninteractive` by default, so `apt` no longer waits for an answer to questions such as the time zone until the run times out. A value set by the caller wins.

### Tools

- `tools_batch` steps can only use tools the run could call directly. A disabled or hidden tool can no longer run as a batch step, and planning-mode restrictions apply as well.
- A terminal wait longer than 30 seconds is shortened to 30 instead of being rejected. A running command reports how long it has run and says that silence is not a hang; `exec_stop` warns against killing installs and builds.
- `file_patch`: in a batch of patches, a later patch may carry a hash older than the Bot's own last write. It is now accepted as long as the file still holds exactly what the Bot wrote, so it no longer fails with `FILE_CHANGED`. Files edited from outside are still refused.
